🚀 Quick Start

1. Download the Miner

The canonical mining software for Lotus Pool is lotus-gpu-miner v0.4.1:

🍎 macOS (x86_64) 🪟 Windows (x86_64) 🐧 Linux (x86_64)

View all releases on GitHub

2. Configure Your Miner

Create a config file at ~/.lotus-miner/config.toml:

mine_to_address = "lotus_YOUR_ADDRESS_HERE"
stratum_url = "pool.lotusia.org:3334"
stratum_worker_name = "rig01"
stratum_password = "x"

Replace lotus_YOUR_ADDRESS_HERE with your actual Lotus payout address.

3. Start Mining

./lotus-miner-cli --stratum-url pool.lotusia.org:3334 --mine-to-address lotus_YOUR_ADDRESS --stratum-worker-name rig01 --stratum-password x

Use the following stratum connection details:

stratum+tcp://pool.lotusia.org:3334

Credentials:

  • Username: Your Lotus (XPI) payout address (e.g., lotus_16PSJN...)
  • Password: x (any password works)

Optionally append a worker name: address.workername (e.g., lotus_16PSJN....rig01)

The pool fee is {{ footer.pool_fee_bps }} bps ({% if footer.pool_fee_bps == "100" %}1.00%{% else if footer.pool_fee_bps == "200" %}2.00%{% else if footer.pool_fee_bps == "50" %}0.50%{% else %}{{ footer.pool_fee_bps }} bps{% endif %}). This is deducted from the gross block reward before miner payouts.

For example, if the block reward is 1,000,000 satoshis and the fee is 1%, the pool takes 10,000 satoshis and distributes 990,000 among miners.

We use PPLNS (Pay Per Last N Shares). The payout window covers the last {{ n_multiplier }}× the expected work needed to find one block.

  • Shares are difficulty-weighted (a 2× diff share counts as 2 shares)
  • The window extends across round boundaries — no discrete "rounds"
  • Long-term miners benefit more (anti-pool-hopping)
  • Early leavers receive less; late joiners receive less

For example, if the window contains 10,000 work units total and you contributed 500, you receive 5% of the net reward.

Payouts are processed automatically every {{ payout_interval_secs }} seconds ({% if payout_interval_secs == "3600" %}1 hour{% else if payout_interval_secs == "1800" %}30 minutes{% else if payout_interval_secs == "900" %}15 minutes{% else %}{{ payout_interval_secs }} seconds{% endif %}).

Blocks must mature to {{ min_confirmations }} confirmations before payouts can be distributed (this is a consensus rule — coinbase rewards cannot be spent until 100 blocks have been mined after them).

Block Lifecycle:

  1. Found — Pool submits a valid block to the network
  2. Confirmed — Block has at least one confirmation
  3. Matured — Block has ≥{{ min_confirmations }} confirmations (coinbase can be spent)
  4. Paid — Payout scheduler distributes rewards to miners

The minimum payout threshold is {{ min_payout_sat }} satoshis. This prevents the creation of dust outputs — tiny transaction outputs that cost more in fees than they're worth to spend.

If your share of a block reward is below this threshold, the amount is stored as dust and carried forward to future payouts. When your accumulated dust + new payout ≥ minimum, the combined amount is paid out. No value is ever lost to dust.

The pool uses VarDiff (Variable Difficulty) — an automatic per-miner difficulty adjustment system.

How it works:

  • Target: One accepted share every {{ vardiff_target_secs }} seconds
  • Retarget: Every {{ vardiff_retarget_secs }} seconds, the pool adjusts your difficulty
  • Start: New miners begin at {{ vardiff_initial_pct }}% of network difficulty
  • Floor: Minimum difficulty is {{ vardiff_min_floor }} (allows tiny miners to participate)
  • Adjustment: ±50% per retarget to prevent wild swings

If your shares arrive faster than {{ vardiff_target_secs }} seconds, difficulty increases. If slower, difficulty decreases. You don't need to configure anything — VarDiff adapts to your hashrate automatically.

Shares can be rejected for several reasons:

Reason Description
Stale Job was replaced by a newer block (new block found)
Duplicate Share already submitted (connection hiccup or misconfiguration)
Invalid Structural errors (bad nonce, extranonce, etc.)
Low-difficulty Share doesn't meet your assigned difficulty
Unauthorized Miner didn't complete subscribe/authorize handshake

High stale rates can indicate network latency. High invalid rates may indicate hardware instability or overclocking issues.

Lotus (XPI) is a blockchain based on the Bitcoin codebase with modifications. It uses the same proof-of-work mining fundamentals — miners compete to find valid blocks by performing hash computations.

This pool is specifically designed for Lotus's consensus rules, including its block structure, coinbase transaction format, and address encoding. You do not need to run a Lotus node to mine — just point your miner to the pool's Stratum endpoint.
